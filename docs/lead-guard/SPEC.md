# Lead Guard — техническое задание и эталонная реализация

**Версия:** 1.0 · **Статус:** эталон, прошёл два независимых аудита и 46 автотестов · **Первое внедрение:** uz-biotech.com

Назначение документа: дать исполнителю (человеку или Claude в новой сессии) всё необходимое, чтобы внедрить на любой сайт с формой заявки два механизма защиты от мусорных лидов **без потери конверсии и без капчи**. Код в комплекте — не набросок, а рабочая реализация: её нужно **подключить и настроить**, а не переписывать. Отклоняться от спецификации можно только там, где это явно разрешено (раздел 9).

---

## 1. Задача и границы

### 1.1. Проблема
Форма заявки «контакт → отправить» собирает три вида мусора: (а) **случайные отправки** живых людей — задели кнопку, двойной тап, Enter в поле; (б) **боты, работающие через страницу** — автокликеры, массовые «формо-боты», программная отправка формы; (в) **боты, бьющие напрямую в API** доставки лида, минуя сайт.

### 1.2. Решение — два независимых слоя
| Слой | Где | Что закрывает |
|---|---|---|
| **Слайдер-подтверждение** («проведите вправо») | браузер | (а) и (б): заявка уходит только после осознанного жеста |
| **Подписанный анти-бот токен** | сервер | (в): API принимает лид только со страницы, с «выдержкой» по времени и с того же домена |

Дополнительно на сервере: honeypot, нормализация контакта, отсечка дублей, лимит по IP, подтверждённая доставка с повтором и логированием.

### 1.3. Что решение сознательно **не** закрывает
Живых людей с кликферм (они свайпнут) и бота, написанного специально под конкретный сайт (исполняет его JS в реальном браузере, берёт токен, ждёт, имитирует жест). Против этого работают только капча или WAF — для лендингов с ценными лидами это осознанный компромисс в пользу конверсии. Путь эскалации: Vercel Firewall (Attack Challenge Mode или rate-limit правило на эндпоинт) — включается одним переключателем, код менять не нужно.

### 1.4. Принципы (нарушать нельзя)
1. **Ни один лид, который принял клиент, не должен потеряться молча.** Сервер не строже клиента; каждый отказ и каждая недоставка — в логах с контактом.
2. **Контакт никогда не попадает в аналитику** (пиксели, GA, Метрика). В хук `onEvent` уходят только нейтральные параметры.
3. **Для человека защита незаметна**: ни ожиданий, ни капч, ни лишних кликов, кроме одного свайпа.
4. **Доступность обязательна**: клавиатура и экранные читалки должны уметь отправить заявку.

## 3. Архитектура и поток данных

```
Загрузка страницы ──► GET /api/lead ──► { token: "<ts>.<hmac>", minAge: 2500 }   (токен в памяти страницы,
                                                                                    фоновое обновление раз в 40 мин)
Человек: вводит контакт → клик «Отправить заявку»
   └─► валидация на клиенте ──(ошибка)──► подсветка поля, событие form_error
   └─► ОК ──► кнопка скрывается, появляется слайдер (фокус на бегунке, клавиатура телефона закрывается)
Человек: берёт бегунок и ведёт до конца
   └─► свайп засчитан (≥3 движения, ≥100 мс, ≥97 %) ──► «Отправляем…», форма заморожена
        └─► ждём «выдержку» токена (обычно 0 мс) ──► POST /api/lead { contact, form_location, token, … } (keepalive)
             └─► ответ ok ──────────────────────────────► флаг в sessionStorage ──► редирект на thank-you
             └─► ответ token_* ──► новый токен, выдержка, ОДИН повтор ──► редирект
             └─► другая ошибка / таймаут 4 с / молчание ──► редирект по дедлайну ≤ 9 с (лид залогирован сервером)
thank-you: consumePendingLead() ──► флаг есть → отправить конверсию (Lead) один раз; нет → ничего
```

Сервер при POST: honeypot → домен (Origin/Referer = host) → токен (подпись, возраст 2.5 с…3 ч) → нормализация контакта → лимит IP → дедуп → Telegram (таймаут 2.5 с, 1 повтор) → 200. Любой отказ — `LEAD_REJECTED {...}` в логах, недоставка — `LEAD_NOT_DELIVERED {...}`.

## 4. Требования к слайдеру (клиент)

### 4.1. Появление и размещение
- Слайдер **не присутствует в HTML** — его создаёт `lead-guard.js` для каждой формы `formSelector` (по умолчанию `form.lead-form`).
- Появляется **только после** клика по кнопке отправки (или Enter в поле) при **валидном** контакте. Невалидный контакт → ошибка поля, слайдер не показывается.
- Вставляется **сразу под кнопкой**: если кнопка лежит в одной строке с полем (контейнер `.field-row`) — под всей строкой. Кнопка на это время скрывается атрибутом `hidden`; CSS-правило `.lead-form button[type="submit"][hidden] { display:none }` **обязательно** (иначе `display:inline-flex` кнопки перебьёт `[hidden]`).
- При появлении фокус переводится на бегунок: на телефоне это закрывает экранную клавиатуру, которая иначе перекрыла бы слайдер; вне модальных окон слайдер прокручивается в зону видимости (`scrollIntoView nearest`). В модалке (`.modal`) не скроллим — диалог должен иметь `max-height: calc(100dvh - 32px); overflow:auto`.
- Появление анимировано (fade + 6 px снизу, 220 мс); при `prefers-reduced-motion` — без анимаций.

### 4.2. Жест
- **Вести можно только бегунок.** `pointerdown` по бегунку начинает жест (`setPointerCapture`), движение меняет положение пропорционально смещению указателя, положение ограничено 0…100 %.
- **Клик/тап по дорожке мимо бегунка ничего не переключает** — бегунок лишь коротко «подёргивается» вправо (анимация-подсказка 450 мс, класс `is-hint`).
- **Свайп засчитывается**, если бегунок доведён до **≥ 97 %** и жест содержал **≥ 3 движения** и длился **≥ 100 мс** с момента захвата. Проверка выполняется при каждом движении и **повторно при отпускании** (быстрый флик, упёршийся в край до истечения 100 мс, засчитывается, когда палец отпущен).
- **Отпустили раньше** — бегунок плавно возвращается в начало (240 мс, ease-out, через `requestAnimationFrame`). Захват бегунка во время отката прерывает откат и продолжает ведение с текущего места.
- Клик по бегунку без движения — ничего.
- `touch-action: none` на дорожке и бегунке: страница не скроллится, пока ведут бегунок.
- События: Pointer Events; для браузеров без них — mouse/touch fallback. `lostpointercapture` / `pointercancel` трактуются как отпускание.

### 4.3. Состояния и визуал
- **Ожидание:** дорожка 54 px, скруглённая, светлая; подпись «Проведите вправо, чтобы отправить» по центру с бегущим бликом (шиммер 2.4 с); бегунок 46 px, круглый, цвет `--primary`, белая стрелка →.
- **Ведение:** заливка дорожки следует за бегунком; подпись тает пропорционально (`opacity = 1 − p/55`, к ~55 % исчезает); бегунок слегка увеличен (scale 1.04), курсор `grabbing`.
- **Подтверждено:** дорожка целиком `--primary`, бегунок белый с галочкой ✓ цвета `--primary`, подпись «Отправляем…» белым слева; лёгкая вибрация `navigator.vibrate(12)` (Android). Бегунок и кнопка заморожены до редиректа.
- Тексты — только в `text` конфигурации (`hint`, `aria`, `confirm`, `sending`).

### 4.4. Доступность
- Бегунок: `role="slider"`, `tabindex="0"`, `aria-valuemin/max/now`, `aria-label`. Клавиши: ←/→/↑/↓ ±10, PageUp/PageDown ±25, Home/End, **Enter/Space — подтверждение**. Клавиатурные шаги не откатываются.
- Для экранных читалок — визуально скрытая кнопка `.sr-only` «Подтвердить отправку заявки» (`type="button"`), доступная с клавиатуры и в AT.
- Фокус-ловушка модального окна должна исключать скрытую кнопку (`button:not([hidden])`) и включать бегунок и sr-кнопку.

### 4.5. Защита от гонок и повторов
- После подтверждения форма **заморожена** (`submitting`): ввод в поле, повторный submit, клики по кнопке игнорируются до редиректа — дубль невозможен.
- До подтверждения: изменение контакта скрывает слайдер и возвращает кнопку (контакт нужно перепроверить); при подтверждении контакт валидируется **повторно** — если стал невалидным, слайдер сбрасывается, кнопка возвращается **активной**, показывается ошибка, отправки нет.
- Honeypot заполнен к моменту свайпа — тихий сброс без отправки.
- Возврат кнопкой «Назад» из bfcache (`pageshow` + `persisted`) → `location.reload()`, чтобы форма не осталась в состоянии «Отправляем…».

## 5. Требования к доставке лида (клиент)

- При `init` страница делает `GET endpoint` и хранит `{ value, at, minAge }`; обновляет фоном каждые 40 мин; на thank-you токен **не** запрашивается.
- Перед отправкой токен **фиксируется** (фоновое обновление не подменяет его) и «выдерживается» до `minAge` (для человека, свайпнувшего через ≥ 2.5 с после загрузки, ожидание = 0). Если токена нет или он старше 2.5 ч — берётся новый (не дольше 3 с), затем выдержка.
- `POST endpoint` с `keepalive: true`, ожидание ответа **≤ 4 с**. Тело: `{ contact, form_location, page, ts, token, …extra }`.
- Ответ `ok` → флаг `pendingFlagKey` в sessionStorage → редирект на `thankYouUrl`. Ответ с `error` вида `token_*` → сбросить токен, взять новый, выдержать, **повторить один раз**. Иная ошибка / таймаут / сеть → редирект без повтора (сервер уже залогировал отказ, если запрос дошёл).
- **Жёсткий дедлайн 9 с** от момента свайпа: что бы ни происходило, человек уходит на thank-you; повтор укладывается в оставшийся бюджет.
- Локальная копия лида в `localStorage` (`storagePrefix + "leads"`) — только для отладки.
- Хук `onEvent(name, detail)`: `form_start`, `form_error`, `cta_click`, `slider_shown`, `lead_confirmed`, `lead_sent {ok, error}`, `lead_redirect`. **Контакт в detail не передаётся никогда.**
- Конверсия (Meta `Lead`, GA, Метрика) отправляется **на thank-you** через `LeadGuard.consumePendingLead()` — флаг возвращается один раз и снимается: нет дублей при обновлении страницы, нет ложных событий при прямом заходе.

## 6. Требования к серверу (`api/lead.js`)

### 6.1. Токен
- `GET` → `{ ok: true, token: "<ts>.<sig>", minAge: 2500 }`, `Cache-Control: no-store`. `sig` = первые 32 hex-символа `HMAC-SHA256(key, ts)`, где `key = SHA-256("lead-token:" + (LEAD_TOKEN_SECRET || TELEGRAM_BOT_TOKEN))`. Отдельный секрет не обязателен; из подписи токен бота не восстанавливается.
- `POST` принимает токен, если: формат `^\d{10,16}\.[a-f0-9]{32}$`; подпись совпадает (`timingSafeEqual`); возраст **≥ 2500 мс** (`token_too_fresh`) и **≤ 3 ч** (`token_expired`). Часы — только серверные.
- `minAge` в ответе GET — единственный источник значения для клиента (константу менять только на сервере).

### 6.2. Порядок проверок POST и коды ответов
| Шаг | Условие | Ответ |
|---|---|---|
| honeypot | поле `website` непустое | `200 {ok:true, skipped:"honeypot"}` — тихо |
| домен | `Origin` (или `Referer`) прислан и его host ≠ host запроса. `Origin: null` = не прислан | `403 bad_origin` |
| токен | отсутствует / подделан / свежий / истёк | `403 token_missing \| token_invalid \| token_too_fresh \| token_expired` |
| контакт | после нормализации короче 3 символов или телефон < 9 цифр | `400 no_contact` |
| лимит IP | > 20 успешных лидов с IP за 10 мин | `429 rate_limited` |
| дубль | тот же контакт (телефон — по цифрам, текст — без регистра) за 10 мин | `200 {ok:true, skipped:"duplicate"}` |
| Telegram | ошибка после повтора | `502 telegram_error \| send_failed` (без деталей Telegram) |
| успех | | `200 {ok:true}` |

Если браузер не прислал ни `Origin`, ни `Referer` — домен не проверяется, решает токен (иначе теряли бы лиды из приватных режимов).

### 6.3. Нормализация контакта (`cleanContact`)
- Вырезать управляющие/невидимые/bidi-символы (`\p{Cc}`, `\p{Cf}`), схлопнуть пробелы, обрезать до 120 символов.
- **Правило совпадает с клиентским**: телефон (`^[+\d][\d\s\-()]*$`) — не менее 9 цифр; иначе — любой текст от 3 символов (ведущие `@` не считаются). Сервер **не отбрасывает** то, что принял клиент («Алишер, +998 90…», ссылка t.me, имя — принимаются как есть).
- Телефон без «+»: ≥ 11 цифр → `+` + как есть; ровно `LOCAL_PHONE_DIGITS` (9) → `+` + `DEFAULT_COUNTRY_CODE` + номер; иначе — как ввели (код страны не выдумываем). Кнопка «Написать» строится только для номера ≥ 11 цифр или для хэндла `@[A-Za-z0-9_]{3,}`.

### 6.4. Доставка и логи
- Telegram `sendMessage` с `AbortSignal.timeout(2500)`; при 429/5xx/сети — один повтор через 700 мс; при 4xx — без повтора. Без `parse_mode` (нет инъекций разметки).
- Каждый отказ → `console.warn("LEAD_REJECTED " + JSON)` с `{error, contact, ip, at}`; недоставка → `console.error("LEAD_NOT_DELIVERED " + JSON)`. Учесть срок хранения логов хостинга (Vercel Hobby ≈ 1 ч, Pro ≈ 1 день) — при критичных лидах подключить Log Drain.
- Лимиты и дедуп живут в памяти тёплого инстанса (best-effort). Порог IP высокий намеренно: мобильные операторы (CGNAT) сажают тысячи людей за один адрес.

## 7. Интеграция по шагам

1. **Разметка каждой формы** (см. `example/index.html`): `<form class="lead-form" data-form-location="…">`, honeypot `<input class="hp-field" name="website" tabindex="-1" autocomplete="off" aria-hidden="true">`, поле `name="contact"`, `<button type="submit">`, необязательно `.field-error` (с `hidden`). Если кнопка в строке с полем — оберните в `.field-row`. Ничего для слайдера в HTML не добавлять.
2. **Подключить** `lead-guard.css` (после стилей сайта) и `lead-guard.js` (`defer`), вызвать `LeadGuard.init({ endpoint, thankYouUrl, onEvent })` на `DOMContentLoaded` страницы с формами. На thank-you — `LeadGuard.consumePendingLead()` для конверсии (см. `example/thank-you.html`).
3. **Сервер:** положить `api/lead.js`; настроить блок «НАСТРОЙКИ САЙТА» (заголовок сообщения, текст кнопки, таймзона, код страны); в хостинге задать `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` (бот должен быть добавлен в группу). Отдельный секрет не нужен.
4. **Дизайн:** при необходимости задать в `:root` сайта `--primary`, `--accent-tint`, `--line`, `--slate`, `--ring` — слайдер подхватит их; без них работают fallback-значения.
5. **Проверка** — раздел 8. Если сайт не на Vercel — раздел 10.

### 7.1. Конфигурация клиента (`LeadGuard.init`)
| Ключ | По умолчанию | Смысл |
|---|---|---|
| `formSelector` | `form.lead-form` | какие формы оборачивать |
| `contactField` / `honeypotField` | `contact` / `website` | имена полей |
| `errorSelector` | `.field-error` | блок ошибки внутри формы |

## 8. Приёмка

### 8.1. Автотесты (обязательно перед публикацией)
```
cd tests && npm install && npm test
```
Ожидается `SERVER: 23 passed, 0 failed` и `CLIENT: 23 passed, 0 failed`. Тесты покрывают: токен (подпись, возраст, домен, `Origin: null`), нормализацию контакта, дубли и лимит IP, повтор и логирование при сбое Telegram; на клиенте — размещение, «только бегунок», откат, флик, клавиатуру, sr-кнопку, повтор при `token_expired`, таймаут, дедлайн, гонки, honeypot, отсутствие PII в `onEvent`.

### 8.2. Ручная проверка в реальном браузере (jsdom не видит CSS)
Десктоп: ввести контакт → «Отправить заявку» → кнопка **исчезла**, слайдер появился под полем с бликом на подписи → клик по правому краю дорожки: бегунок дёрнулся и остался → бросить бегунок на середине: плавно вернулся → довести до конца: белый бегунок с галочкой, «Отправляем…», страница «спасибо», в группе сообщение с контактом (с «+»), временем и кнопкой «Написать в Telegram» → обновить «спасибо»: конверсия не задублировалась.
Телефон (iOS Safari + Android Chrome): то же; при появлении слайдера клавиатура закрылась, слайдер целиком на экране (в т. ч. в модалке); страница не скроллится во время ведения.
Прямой запрос без страницы: `curl -X POST https://<домен>/api/lead -H 'Content-Type: application/json' -d '{"contact":"+998901234567"}'` → `403 token_missing`, в логах `LEAD_REJECTED`.

## 9. Что разрешено менять, а что нет

**Можно:** тексты; цвета через переменные; `doneAt` в пределах 90…97 (ниже — начинаем засчитывать случайные короткие движения); `DEFAULT_COUNTRY_CODE`/`LOCAL_PHONE_DIGITS`; заголовок и кнопку сообщения; таймзону; `IP_LIMIT` (не ниже 20 для мобильного трафика); `onEvent`.

**Нельзя без пересмотра тестов:** делать сервер строже клиента; убирать ожидание ответа сервера или дедлайн; отправлять конверсию на странице формы; передавать контакт в аналитику; понижать `TOKEN_MIN_AGE_MS` ниже 2000 или поднимать выше 3000 (первое ослабляет защиту, второе заставит ждать быстрых людей); заменять бегунок на `<input type=range>` (клик по дорожке телепортирует значение — именно от этого ушли).

## 10. Другие хостинги
Логика сервера платформенно-нейтральна; меняется только обёртка `handler(req, res)`:
- **Netlify Functions:** `exports.handler = async (event)` — `event.httpMethod`, `event.headers`, `JSON.parse(event.body)`, возврат `{ statusCode, body }`; редирект `/api/lead → /.netlify/functions/lead` в `netlify.toml`.
- **Cloudflare Pages Functions:** `onRequestGet / onRequestPost(context)` — `context.request.headers.get(...)`, `await request.json()`, `Response.json(...)`; переменные — `context.env`; `crypto` → Web Crypto (`crypto.subtle`), `AbortSignal.timeout` доступен.
- Любой Node-сервер (Express): смонтировать `handler` на `GET/POST /api/lead`, тело — `express.json()` (клиент шлёт `application/json` строкой).
Перенести обязательно: `signToken`/`verifyToken`/`sameSite`/`cleanContact`/`dedupeKey`/лимиты/`sendTelegram` и порядок проверок из 6.2.

## 11. Совместимость
Клиент: Chrome/Edge/Firefox/Safari последних 3 лет, iOS Safari 13+, Android Chrome; без PointerEvent — mouse/touch fallback; без `requestAnimationFrame` — мгновенный откат; без `fetch`/`Promise` модуль не работает (такие браузеры не являются целью). Сервер: Node 18+ (`fetch`, `AbortSignal.timeout`, `crypto`).
